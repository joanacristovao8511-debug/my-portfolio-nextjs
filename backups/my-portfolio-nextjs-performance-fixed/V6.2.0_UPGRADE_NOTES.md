# V6.2.0 — Authentication & Admin Security Hardening

## Changes

- Added database-authoritative `requireAdmin()` checks for privileged server actions.
- Admin authorization now verifies current role, account status, and lock state against PostgreSQL instead of trusting only a JWT role claim.
- Reworked credential bootstrap so environment credentials can create the first admin only when that email does not already exist.
- Removed the previous bootstrap path that could authenticate with environment credentials even when the database was unavailable.
- Added failed-login tracking with a 5-attempt / 15-minute account lockout using the existing `AdminUser` fields.
- Successful authentication resets failed-login state and records `lastLoginAt`.
- Existing administrators are always authenticated against their bcrypt password hash.
- Added an 8-hour JWT session lifetime with hourly session updates.
- Authenticated administrators are redirected away from `/admin/login`.
- Added a minimum 12-character bootstrap password requirement to runtime bootstrap validation and database seeding.
- Login inputs now use standard username/current-password autocomplete semantics.

## Validation status

The source was inspected and the archive was tested with `unzip -t`. A full dependency install/build was not completed in this packaging environment, so no production build success is claimed.
